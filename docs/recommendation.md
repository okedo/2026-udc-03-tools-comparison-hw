# Рекомендація для команди (Task D)

Короткий висновок: Рекомендується зробити GitHub Copilot CLI основним інструментом (primary), а Claude Code — додатковим (secondary) для великих автономних сесій.

## Рекомендований основний (primary) інструмент

**GitHub Copilot CLI**

Чому: Task A показав, що Copilot CLI краще інтегрується з GitHub (PR/Issues, корпоративна індексація) й має сильні enterprise-функції (SSO, audit-логи, data residency). Task B підтвердив, що Copilot був економічно ефективним і швидким при вирішенні задачі bug-fix. Це робить його оптимальним вибором для команд, що працюють у великих хмарних репозиторіях і цінують контроль і відповідність.

## Рекомендований додатковий (secondary) інструмент

**Claude Code** — для сценаріїв: великі локальні рефактори, автономні agent-цикли та завдання з дуже великим контекстом.

Чому: Task A/B показали, що Claude Code має велику автономність та велике контекстне вікно, що корисно для складних локальних сесій (міграції, великі рефакторинги).

## Ключові компроміси (trade-offs)

- Ціна vs автономність: Copilot дешевший і краще інтегрований з GitHub; Claude дорожчий, але потужніший для автономних задач.
- Приватність/enterprise: для чутливих даних використовувати корпоративні підписки та перевіряти налаштування, щоб дані не використовувалися для навчання моделей.
- Портативність vs глибина автоматизації: agent-специфічні фічі знижують переносимість workflows між інструментами.

## Ризики та застереження

- Vendor lock-in та зміни цінової політики: підготувати fallback-процедури та зберігати AGENTS.md синхронізованим між інструментами.

Кроки впровадження: встановити Copilot CLI як стандарт, документувати використання Claude Code в AGENTS.md та провести коротке навчання для команди щодо політик приватності і бюджету.
